I. QUY CHUẨN THÔNG ĐIỆP COMMIT (COMMIT MESSAGE STANDARDS)
--------------------------------------------------------------------------------
Một commit message chuẩn mực gồm 2 thành phần chính:
   Cú pháp: <loại commit>(<phạm vi>): <nội dung tóm tắt ngắn gọn bằng tiếng Anh>

1. LOẠI COMMIT (MUST - BẮT BUỘC):
   Là thành phần không thể thiếu của một commit message, để xác định rõ commit đó
   có mục đích là gì. Các loại commit bao gồm:

   - feature  : tính năng mới được bổ sung vào hệ thống.
   - bugfix   : sửa lỗi phát sinh cho hệ thống.
   - refactor : sửa code, tái cấu trúc nhưng không thêm feature và cũng không fix bug.
   - docs     : thêm mới hoặc thay thế/cập nhật tài liệu kỹ thuật (documentation).
   - chore    : những sửa đổi nhỏ nhặt về cấu hình, dọn dẹp không liên quan đến logic code.
   - style    : những thay đổi về định dạng, căn lề, giao diện CSS không làm đổi logic code.
   - perf     : cải thiện performance, tối ưu hóa tốc độ xử lý hoặc thuật toán.
   - vendor   : cập nhật phiên bản cho các gói tài nguyên, file nén, dependencies.

2. PHẠM VI (OPTIONAL - TÙY CHỌN NHƯNG KHUYÊN DÙNG):
   Cũng dùng để phân loại commit, nhưng chi tiết hơn về ý nghĩa một chút, trả lời
   cho câu hỏi: "Commit này thêm mới chức năng gì, fix chức năng gì?".
   Ví dụ định dạng:
     VD : feature(login_sso): bugfix( user_profile )

3. QUY ĐỊNH VỀ NGÔN NGỮ & ĐỘ DÀI (ENGLISH & CONCISENESS):
   - Ngôn ngữ: BẮT BUỘC sử dụng TIẾNG ANH (English) ngắn gọn, súc tích và chuyên nghiệp.
   - Ngữ pháp: Sử dụng thể mệnh lệnh ở hiện tại (Imperative mood - ví dụ: "add", "fix",
     "update", "optimize", không dùng "added", "fixing", "updates").
   - Độ dài: Ngắn gọn, trọng tâm (khuyến nghị dưới 60 ký tự), không viết hoa bừa bãi và
     không kết thúc bằng dấu chấm câu.

4. VÍ DỤ ÁP DỤNG THỰC TẾ CHO DỰ ÁN SUDOKU (ENGLISH CONVENTIONAL COMMITS):
   - feature( devtools ) : add decoupled qa console and testing cheats
   - style( gameplay )   : set normal font weight for user cells and red error background
   - docs( devtools )    : add testing tools documentation and update tree
   - feature( scoring )  : implement scoring system and streak penalties
   - feature( profile )  : revamp overview stats card and best score
   - bugfix( timer )     : fix timer continuing when pause modal opens
   - bugfix( board )     : resolve duplicate cell highlight on rapid input
   - refactor( engine )  : streamline backtracking sudoku solver
   - docs( css )         : document architecture of 6 css modules
   - chore( git )        : ignore testing zip archives

II. NGUYÊN TẮC BẤT DI BẤT DỊCH VỀ GIT (CRITICAL GIT RULES)
--------------------------------------------------------------------------------
1. TUYỆT ĐỐI KHÔNG TỰ TIỆN CHẠY LỆNH "git push":
   - Tất cả các thao tác mã hóa chỉ được lưu trữ và tạo commit ở máy tính Local
     (thông qua `git add` và `git commit -m "..."`).
   - Quyền đẩy mã lên GitHub (`git push`) hoàn toàn thuộc về người dùng (USER).
   - Chỉ được hướng dẫn người dùng lệnh push hoặc chỉ chạy khi người dùng ra lệnh rõ ràng.

2. GOM COMMIT TRƯỚC KHI PUSH (TRÁNH DẤU X ĐỎ GITHUB ACTIONS):
   - Dự án được cấu hình GitHub Pages tự động build & deploy mỗi khi có push mới.
   - Nếu commit xong mà push ngay lập tức liên tục từng commit, tiến trình GitHub Actions
     đang chạy sẽ tự động bị HỦY BỎ (Cancelled) và hiện dấu chéo đỏ:
     `❌ pages build and deployment / deploy (dynamic) Cancelled after 12s`
   - BÍ QUYẾT: Hãy commit đầy đủ các đợt ở local trước, sau đó chỉ chạy đúng 1 lần:
     `git push origin main`
     => Giúp GitHub Actions chỉ kích hoạt 1 luồng duy nhất và hiện tích xanh `✓ 3/3` tuyệt đẹp!

III. NGUYÊN TẮC VỀ FILE NÉN & KHỞI CHẠY OFFLINE (ZIP & LAUNCHER RULES)
--------------------------------------------------------------------------------
1. QUY TẮC VỀ FILE "ChoiGame.bat":
   - File `ChoiGame.bat` được thiết kế để hỗ trợ người chơi Windows nhấp đúp 1-click là chơi ngay.
   - File này CHỈ ĐƯỢC PHÉP NẰM BÊN TRONG CÁC FILE NÉN .ZIP.
   - TUYỆT ĐỐI KHÔNG ĐƯỢC để file `ChoiGame.bat` thừa thãi ra ngoài thư mục gốc của repository.

2. QUẢN LÝ CÁC FILE NÉN ĐẶC BIỆT (RELEASE & TESTING ARCHIVES):
   - `Sudoku-Game-v1.0.zip`:
     + Bản lưu trữ nguyên bản cột mốc phát hành đầu tiên (Release v1.0).
     + TUYỆT ĐỐI KHÔNG ĐƯỢC chỉnh sửa, ghi đè hay thay đổi nội dung file này.
   - `Sudoku-Game-v1.1.zip`:
     + Bản lưu trữ cột mốc chính thức Release v1.1 (Cài đặt, Song ngữ i18n, Dark Mode, Cấp bậc 9 Rank).
     + TUYỆT ĐỐI KHÔNG ĐƯỢC chỉnh sửa, ghi đè sau khi đã phát hành.
   - `Sudoku-Game-testing.zip`:
     + Bản nén cập nhật liên tục toàn bộ tính năng và mã nguồn mới nhất cho quá trình phát triển (hiện chứa toàn bộ tính năng chuẩn bị cho bản v2.0).
     + Mỗi khi hoàn thành một đợt nâng cấp mới, hãy rebuild file này để thử nghiệm offline ngay lập tức.
     + Khi người dùng sẵn sàng ra mắt chính thức v2.0, file này mới được đóng gói và đặt tên thành Sudoku-Game-v2.0.zip.

3. NGUYÊN TẮC TINH GỌN GÓI PHÁT HÀNH CHO NGƯỜI CHƠI (NO DOCS IN ZIP):
   - Các file zip phát hành (như `Sudoku-Game-v1.1.zip` hay `Sudoku-Game-testing.zip`)
     được tinh gọn tối đa (~77 KB) để người chơi tải về và nhấp đúp `ChoiGame.bat` là chơi ngay.
   - TUYỆT ĐỐI KHÔNG đóng gói thư mục `docs/` hay `screenshots/` vào file zip.
     Người dùng và lập trình viên muốn nghiên cứu kiến trúc hệ thống sẽ xem trực tiếp
     trên repository GitHub.

4. QUY ƯỚC ĐÁNH SỐ PHIÊN BẢN (SEMANTIC 2-DIGIT VERSIONING):
   - Thay vì dùng 3 chữ số rườm rà (v1.0.0, v1.0.1...), dự án thống nhất dùng chuẩn
     2 chữ số tinh gọn: `v1.0`, `v1.1`, `v1.2`, `v2.0`...
   - Tất cả các link trên README, tag git và tên file zip đều tuân theo chuẩn này.

IV. NGUYÊN TẮC CÔNG NGHỆ & MÃ NGUỒN (CODE CONSTRAINTS)
--------------------------------------------------------------------------------
1. TUYỆT ĐỐI ZERO-DEPENDENCY:
   - Không thêm bất kỳ package npm, node_modules hay thư viện CDN nào từ bên ngoài.
   - Toàn bộ game chạy thuần 100% bằng HTML5, CSS3 và ES6+ nguyên bản.

2. KHÔNG DÙNG HỘP THOẠI TRÌNH DUYỆT NGUYÊN THỦY:
   - Cấm dùng `window.alert()` hoặc `window.confirm()`.
   - Bắt buộc dùng `App.alert(title, msg)` hoặc `App.confirm(title, msg)` để đảm bảo
     trải nghiệm mượt mà và đồng bộ thiết kế thẩm mỹ.

3. XỬ LÝ LỖI CACHE TRÌNH DUYỆT (BROWSER CACHE BUSTING):
   - Khi chỉnh sửa các file CSS hoặc JS, trình duyệt của người dùng có thể giữ lại
     bản cache cũ.
   - Luôn nhắc người dùng nhấn tổ hợp phím `Ctrl + F5` (hoặc mở thẻ ẩn danh) để
     trình duyệt tải lại toàn bộ tài nguyên mới nhất.

4. NGUYÊN TẮC THIẾT KẾ 100% CHO PC (PC EXCLUSIVE DESIGN):
   - Toàn bộ giao diện được tối ưu hóa chuyên biệt cho màn hình máy tính (PC / Laptop).
   - Tab Hồ sơ (Profile) phải luôn nằm trọn vẹn trong đúng 1 màn hình duy nhất
     (tuyệt đối không để phát sinh thanh cuộn dọc trên màn hình desktop/laptop).
   - Tự động hiển thị màn hình thông báo lịch sự khi người dùng truy cập từ thiết bị
     di động hoặc màn hình hẹp (< 820px).

V. QUY TẮC ĐỒNG BỘ TÀI LIỆU TOÀN DIỆN (DOCUMENTATION INTEGRITY RULE - BẮT BUỘC)
--------------------------------------------------------------------------------
1. TẦM QUAN TRỌNG TỐI CAO CỦA THƯ MỤC docs/:
   - Thư mục `docs/` là "Bộ não kiến thức" lưu trữ toàn bộ sự thật kỹ thuật (Single Source of Truth)
     của toàn hệ thống Sudoku Web.
   - Khi làm việc trong các phiên độc lập hoặc sau khi bị nén ngữ cảnh (context truncation),
     AI Assistant (Antigravity) sẽ dựa vào `docs/` để thấu hiểu kiến trúc, bảng màu, logic và
     các ràng buộc kỹ thuật mà không cần phải đoán mò hay suy diễn sai lệch.

2. NGUYÊN TẮC BẤT DI BẤT DỊCH VỀ ĐỒNG BỘ TÀI LIỆU:
   - BẤT KỲ khi nào có sửa đổi logic, bổ sung tính năng mới, tái cấu trúc CSS, thêm file JavaScript
     hoặc tinh chỉnh giao diện người dùng:
     => LẬP TỨC cập nhật đồng bộ các tài liệu tương ứng trong thư mục `docs/` trong cùng phiên làm việc!
   - Tuyệt đối KHÔNG ĐƯỢC để code chạy trước mà tài liệu `docs/` bị lỗi thời hoặc bỏ sót.
   - Bảng phân công trách nhiệm tài liệu khi cập nhật hệ thống:
     * `docs/01_project_overview.txt`           : Kiến trúc thư mục, triết lý sản phẩm, tổng quan tính năng.
     * `docs/02_architecture_and_modules.txt`   : Chi tiết 11 module JavaScript, hàm mới, localStorage schema.
     * `docs/03_game_logic_and_rules.txt`       : Thuật toán, luật chơi, hệ thống tính điểm, cấp bậc Rank kỳ thủ, trợ năng.
     * `docs/04_ui_ux_design_system.txt`        : Bảng màu (Light/Dark tokens), typography, quy chuẩn layout PC, modal spec.
     * `docs/05_dev_guidelines_and_notes.txt`   : Quy chuẩn Git commit, quy tắc zero-dependency, hướng dẫn bảo trì.
     * `docs/06_css_styling_and_architecture.txt`: Bóc tách chi tiết từng file CSS, quy tắc class, animation keyframes.
     * `docs/07_developer_tools_and_testing.txt`: Hệ thống cheat HUD, phím tắt QA, kịch bản test tự động.
